# Структура базы данных

СУБД — PostgreSQL 14+. Схема управляется только Django migrations; ручное изменение таблиц в production не допускается. Актуальное состояние проверяется командой `manage.py showmigrations`.

## Основные сущности

| Приложение | Сущности | Назначение и ключевые связи |
|---|---|---|
| `employee` | `Employee`, `GroupProxy` | Пользователь с организацией, GUID, счётчиком ошибок и блокировкой; роли хранятся как Django groups |
| `journal` | `Irp`, `IrpTheme`, `IrpHistory`, `IrpAnswer`, `IrpFile`, `XmlFiles` | Карточка обращения; тема и сотрудники; история, ответы и вложения принадлежат обращению |
| `exchange` | `ImportLog` | Результат обработки файла, организация, количество строк и текст FLCP |
| `core` | `EventLog` | Прикладная трасса события: модуль, тип, пользователь, IP, результат, начало/завершение и длительность |
| `system` | `Conversation`, `MessageThread`, `MessageReply`, `MessageAttachment` | Диалоги, темы, ответы, отметки прочтения и вложения |
| `system` | `TaskJob`, `TaskRun`, `TaskNote`, `TaskFile`, `TaskReport` | Описание автоматизированного задания и история запусков |
| `system` | `NewsCategory`, `NewsItem`, `DocCategory`, `SystemDocument` | Новости и эксплуатационная документация |
| `system` | `UserTableViewPref` | Персональные колонки, порядок, сортировка и фиксация таблицы |

## Ключевые инварианты

- `Employee.guid` уникален; `(user, table_key)` уникален для настроек таблицы.
- Статус обращения хранится явно; закрытие требует `date_close` и `result`, дата закрытия не раньше даты поступления.
- `IrpHistory` удаляется вместе с обращением; ссылки на сотрудников используют защитное или nullable-поведение согласно назначению поля.
- Один `TaskJob` захватывается условным атомарным UPDATE; зависшие `TaskRun` закрываются scheduler по таймауту.
- `ImportLog` фиксирует результат, а бизнес-изменения одного входного файла выполняются атомарно.

## Персональные и файловые данные

БД содержит идентификационные и контактные сведения заявителей. Доступ ограничивается RBAC и организационным scope. Файлы физически находятся в `media`, но выдаются только через авторизованные endpoints; прямую публикацию `MEDIA_ROOT` веб-сервером включать нельзя.

Для точного машинного описания используйте миграции в `apps/*/migrations/`; этот документ объясняет логическую структуру и не заменяет DDL конкретного релиза.
