# Форматы файлов обмена

## Поддерживаемые входные файлы

| Маска | Формат | Назначение |
|---|---|---|
| `G1*.xml` | XML | обращения граждан |
| `users*.xml` | XML | сотрудники, upsert по GUID; новые записи создаются неактивными |
| `*.xlsx` | Office Open XML | табличный импорт обращений через тот же ФЛК |

Максимальный размер файла — 20 МБ. XML разбирается без внешних сущностей, сетевого доступа и режима huge tree. Для XML сначала выполняется XSD-проверка, затем единый форматно-логический контроль и атомарная запись файла целиком.

## Каталоги и жизненный цикл

Автоматический обмен использует `exchange/in/<org>`, `exchange/out/<org>` и `exchange/archive/<org>`. После обработки входной файл переносится в архив с уникальным именем, а протокол создаётся в `out`. Существующие артефакты не перезаписываются. Каталоги могут находиться на разных файловых системах: после подтверждённой копии источник удаляется, поэтому один файл не подхватывается планировщиком повторно.

Организации текущего справочника: `81000` ТФОМС, `81001`, `81007`, `81008` СМО. Веб-загрузка дополнительно проверяет право роли и допустимую организацию отправителя.

## Протокол FLCP

Ответ — XML в кодировке Windows-1251:

```xml
<?xml version="1.0" encoding="windows-1251"?>
<FLCP FNAME="G1_example.xml" FNAME_I="G1_example.xml">
  <PR OSHIB="0" COMMENT="Ошибок нет, обработано записей: 1."/>
</FLCP>
```

`OSHIB="0"` означает успешную обработку. `OSHIB="41"` означает ошибку; атрибуты `IM_POL`, `N_ZAP` и `COMMENT` указывают поле, запись и описание. При коде 41 бизнес-данные файла не сохраняются.

## Основные поля ФЛК обращений

Обязательны: `n_irp`, `irp_type`, `date_create`, `way`, `how`, `theme`, `otv_t`, `otv_kon`, `data_plan`, `employee_1`. Значения видов, источников, способов, организаций, линий, исходов и типов жалоб проверяются по справочникам приложения; тема должна существовать в актуальной версии 3, сотрудники разрешаются по GUID.

XLSX принимается как безопасный ZIP-контейнер: входной файл ограничен 20 МБ, суммарный распакованный объём — 100 МБ, количество внутренних элементов — 1000. Зашифрованные контейнеры, повреждённый ZIP и элементы с абсолютными либо родительскими путями отклоняются до запуска `openpyxl` и загрузки строк в БД.

Для `users*.xml` обязательны `USER_FULLNAME` и `USER_UUID`; `USER_EMAIL`, если передан, должен быть валидным email.

## Граница подтверждённого контракта

Имена XSD, маски и семантика FLCP перенесены из исходной системы. Официальные Приложения №1–10 и исходный XSD-субмодуль заказчиком не предоставлены, поэтому точное внешнее соответствие полей и шаблона XLSX нельзя считать принятым. До получения эталонов изменения формата должны сопровождаться версионированными fixtures и согласованием владельца интеграции.
