# Журнал решений

## 2026-09-10 Security foundation

- Прямые `FileField.url` не являются механизмом авторизации. Все чувствительные вложения выдаются через Django endpoints, которые проверяют доступ к родительскому объекту.
- Общесистемная документация остаётся доступной всем аутентифицированным пользователям по существующему endpoint; вложения обращений наследуют org scope, сообщения — membership, задачи — admin role.
- Production-конфигурация обязана завершаться ошибкой без отдельных сильных `SECRET_KEY` и `JWT_SECRET`. HTTPS, secure cookies и HSTS включены по умолчанию и могут быть явно изменены только окружением для контролируемого TLS-терминатора.
- База PostgreSQL не публикуется на host в production compose. `media` и `exchange` хранятся в именованных volumes.
- `PROMPT_v3` используется как backlog UX, но не расширяет ТЗ там, где вводит таск-трекер, realtime или социальные функции без подтверждения бизнес-процесса.

## 2026-09-10 Atomic exchange import

- Файл обмена является минимальной атомарной единицей: ошибка XSD, ФЛК или сохранения любой строки откатывает все изменения этого файла, включая `XmlFiles`.
- Ошибочный файл архивируется, а FLCP и `ImportLog` сохраняются вне откатанной бизнес-транзакции, чтобы участник обмена получил диагностический протокол.
- XML обрабатывается parser с `resolve_entities=False`, `no_network=True`, `huge_tree=False`; UI и автоматический импорт отклоняют файлы больше 20 МБ.
- Артефакты с повторными именами получают уникальный суффикс. Существующие входные файлы, архивы и протоколы никогда не перезаписываются.
