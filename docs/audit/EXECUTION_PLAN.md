## Журнал выполнения

### 2026-09-11 — исходная точка остаточного плана

- Функциональный backlog закрыт кроме требований, зависящих от отсутствующих приложений к ТЗ.
- UI-вертикали 001–008 реализованы, но полная матрица разрешений, тем, ролей и состояний ещё не доказана.
- Накопленные локальные коммиты ожидают production image gate; прямой `curl` к `files.pythonhosted.org` также завершается TLS-ошибкой.
- Следующий контрольный результат: этап 1, доступность и сообщения об ошибках форм.

### 2026-09-11 — этап 1: доступность форм

- Общий клиентский слой связывает label с первым рабочим контролом `.field`, не требуя ручного дублирования логики во всех шаблонах.
- Help text и серверные ошибки включаются в `aria-describedby`; ошибочные поля получают `aria-invalid`, динамическая ошибка — `role=alert` и удаляется из accessible description после исправления.
- AX-дерево формы создания обращения подтверждает доступные названия полей и обязательность; синтаксис JS и Django system check проходят.
- Следующий этап: матрица viewport/theme/font-scale для ключевых маршрутов.

### 2026-09-11 — этап 2: визуальная матрица

- Добавлен воспроизводимый Chrome DevTools прогон `scripts/visual_qa.mjs`, не требующий npm-зависимостей и использующий только локальную QA-учётную запись.
- Проверены 11 ключевых маршрутов в шести размерах окна: 694×869, 1024×768, 1280×800, 1366×768, 1440×900 и 1920×1080.
- Для 694, 1024 и 1920 дополнительно проверены тёмная тема и увеличенный шрифт; всего выполнено 132 сценария.
- Автоматическая проверка не обнаружила переадресаций на вход и горизонтального переполнения документа. Выборочно просмотрены мобильная форма, тёмная таблица задач и сообщения с увеличенным шрифтом.
- Следующий этап: матрица ролей и состояний, начиная с доступов и пустых/заполненных представлений.

### 2026-09-11 — этап 3: роли и системные состояния, итерация 1

- Визуальная матрица повторена для администратора, ОП1 и СП1: суммарно 396 сценариев.
- Для ОП1 подтверждены ожидаемые запреты на события, задачи и пользователей; для СП1 дополнительно подтверждён запрет на чужую карточку обращения. Неожиданных разрешений или запретов нет.
- Автоматический прогон теперь отличает ожидаемую 403 от ошибки настройки роли.
- Обнаружена необработанная системная страница Django; вместо неё добавлены согласованные с порталом адаптивные страницы 403, 404 и 500 с понятным следующим действием.
- Отдельный прогон из 156 сценариев подтвердил пустые и заполненные разделы, а также зарегистрированное, просроченное и закрытое обращения во всех размерах, тёмной теме и с увеличенным шрифтом.
- Этап закрыт без document overflow и расхождений ожидаемой матрицы доступа. Следующий этап: сквозные операции создания, изменения и получения результата.

### 2026-09-11 — контроль публикации после этапа 3

- Полностью прошли `uv sync --frozen`, Ruff, pytest, проверка миграционного drift, базовый и production Django system check, а также `docker compose config --quiet`.
- Обязательный fetch `origin/main` не выполнен: локальный DNS не разрешает `github.com`.
- Docker build остановился до чтения Dockerfile-слоёв: Docker Desktop не смог разрешить `registry-1.docker.io` и `ghcr.io`.
- Push намеренно не выполнен без предварительного merge базы и production image gate.

### 2026-09-11 — этап 4: сквозные операции, итерация 1

- LiveServer E2E расширен до настоящих cookie/CSRF POST-потоков с последующими редиректами и проверкой результата в БД.
- Подтверждены регистрация и закрытие обращения, построение отчёта и скачивание XLSX, создание диалога/темы/ответа, публикация новости, создание задачи с заметкой и отчётом, а также создание пользователя с ролью СП1.
- Сквозной отчёт выявил вывод `None` в незаполненных числовых колонках приложения №1. Формирователь строк теперь выдаёт нули; добавлена регрессия для HTML и расчётного слоя.
- Добавлен multipart-клиент без тестовых обходов HTTP. Им проверены загрузка PDF-документа и XML обмена, переход к протоколу ФЛК, успешный ImportLog и импорт пользователя.
- Файловые операции изолированы временными MEDIA/EXCHANGE-каталогами и не оставляют артефакты в рабочем дереве.
- Этап закрыт. Следующий этап: вторичный UI debt — inline styles, destructive confirmations и состояния отправки.

### 2026-09-11 — этап 5: вторичный UI debt, итерация 1

- Удалено дублирование JavaScript-подтверждений из экранов новостей; обработка `data-confirm` теперь едина для всего портала.
- Подтверждения добавлены к удалению документов и заметок, а также к блокировке пользователя; уже существующие удаления новостей используют тот же механизм.
- После подтверждённой отправки активная кнопка блокируется, получает `aria-busy` и понятную подпись «Отправка…», что предотвращает повторные POST. При возврате из browser back-forward cache состояние корректно восстанавливается.
- Следующая итерация: перенос оставшихся значимых inline-стилей и обработчиков в общие CSS/JS-компоненты.
